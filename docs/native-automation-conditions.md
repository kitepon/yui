# Appleアプリの戻り幅と打ち切り記録

## 対応内容

2026年10月14日、サーバーのセンサー条件の戻り幅と、分析の`stopped_by`にiPhone・iPad・Mac Catalystの共通画面を対応させた。実行時の判定はサーバーに保ち、アプリには追加していない。

- センサー条件を読み取るモデルに任意の`hysteresis`を追加した。未設定と0は従来の表示を保つ。
- 編集画面に見出し・枠・単位付きの戻り幅欄を追加した。文字列のまま編集し、空欄を保持する。0〜100、小数点第一位までを受け付け、全角数字と小数点も同じ値として読む。不正な入力で保存すると理由を表示し、入力欄へフォーカスを戻す。
- センサー条件の保存には戻り幅を必ず含め、解除時は0を送る。他のトリガーには含めない。センサー条件の一覧には、0より大きい戻り幅を添える。
- `stopped_by`の詳細から打ち切った行の名前を表示し、`ts`から`until`まで1分以上なら終了時刻も添える。機器名がない記録も表示する。壊れたJSONや継続時刻は読み取れないことを明示し、他の理由の表示は保つ。

## 検証

- `YuiAutomationTests`の6件がiPhoneシミュレーターとMac Catalystで成功した。旧形式の読取、3種類の比較条件の表示、入力の境界と全角、他のトリガーの送信、個別保存口への0.2と0の送信、保存失敗時の維持、59秒と60秒の表示境界、壊れた記録を確認した。送信は`URLProtocol`で置き換え、本番の家や機器を変更していない。
- iPhoneの開発用デモ画面で、一覧の「戻り幅0.2」、編集欄への読込、置換、空欄、全角入力、空欄での保存案内を確認した。分析のデモ記録でも、打ち切った行の名前と継続時刻の表示を確認した。
- Macの開発用デモ画面で、編集メニューの全選択、削除による空欄、0.3の再入力、空欄での保存案内を確認した。分析の打ち切り記録も表示できた。
- `npm run lint`、`npm run typecheck`、`npm test`、`npm run build:dev`が成功した。
- Nodeの自動テストは365件。アプリ本体の`Models.swift`と`YuiClient.swift`を使った検証用プログラムで、本番の審査用アカウントへログインした。家の機器がすべてデモであることを確認してから、無効の試験用オートメーションを作成し、戻り幅0.2の保存と再読取、0での解除、分析の取得、試験用オートメーションの削除を確認した。機器・場面・既存オートメーションの構成は試験前と一致した。通常のアプリのKeychainは使っていない。

初回のlintは、別作業の`.claude/worktrees/`内のビルド生成物まで走査し、4,834件の問題を報告した。ESLintの除外設定へその作業用チェックアウトだけを追加し、再実行は成功した。別作業のファイルと生成物は変更していない。

XcodeBuildMCPのタップは成功応答でも画面を開けなかったため、その応答を操作成功とは扱わなかった。Jev Desktopの既定の実行ファイルではアプリを見つけられず、公開オプション`--bin`で導入済みのagent-desktopを選ぶと、Macの編集画面を開けた。入力と最終表示はコンピューター操作APIで照合した。

配布予定の版とビルド番号は`ios/project.yml`を正本とする。アーカイブ・書き出し・Apple検証の結果は、完了後に本節へ追記する。
